## 播放与批量取消边界

取消策略沿用经核对的 Jellyfin 版本。当前 `12.2.0` 的 PlaybackInfo 允许探测但传 `CancellationToken.None`，请求开始不等于一定探测，客户端退出／停止播放也不向该探测传入取消。插件不新增客户端停止到探测取消的机制；本次执行若成功、结果已保存且 Manifest 一致，客户端退出不单独阻止指纹提交。普通媒体、旧 STRM、禁用和 `allowMediaProbe=false` 的原生委托与权限边界保留。

按用户要求的 A 实质范围调整，已关闭的 Slice 1 播放原型不增加成功返回后额外检查取消的防御性约束，不要求人为注入可取消 token 的验收；原 token 委托、原生取消异常保留基线并传播及已有回归仍保留。REQ-PROBE-003 在 Slice 2 的可取消共享执行中覆盖探测中与提交前取消；Slice 3 验证真实批量停止。任务停止由 Jellyfin 向 `IScheduledTask.ExecuteAsync` 的 token 发出取消，插件停止分页／排队并撤销该任务的等待；单个等待者退出不把仍服务其他等待者的共享执行标记为取消。固定源码及接口见 [兼容性](compatibility.md#播放与批量取消语义)。这一边界不将尚未运行的真实取消或批量停止验收改为 PASS。

## 核心决策表

前提：受支持版本化 STRM、已有必要主流、存在历史指纹。无历史时按首次接管处理；allowMediaProbe=false 只作判断，不执行要求的探测、不接受变化指纹。

| URL | 新旧有效 SHA-1 | 新旧有效 Size | 决策 |
|---|---|---|---|
| 改变 | 任意 | 任意 | RequireProbe，原生更新地址与媒体流 |
| 不变 | 相同 | 任意 | SkipProbe |
| 不变 | 不同 | 任意 | RequireProbe |
| 不变 | 不可比较 | 相同 | SkipProbe |
| 不变 | 不可比较 | 不同 | RequireProbe |
| 不变 | 不可比较 | 不可比较 | SkipProbe，记录信息不足 |

缺少主流优先要求探测。Modified 不参与。URL 比较涵盖完整有效地址及签名查询参数；签名变化也可能要求探测。无可比 SHA-1 且同 URL／同大小的远程替换无法可靠发现，文档不得宣称识别所有替换。

## 输入协议

V4.2 未重新定义格式，继续使用已有版本 1 输入合同：

```text
# strm-probe-version:1
# strm-probe-sha1:aabbccddeeff0011223344556677889900112233
# strm-probe-size:10737418240
https://media.example.invalid/video/movie.mkv
```

版本是协议版本；SHA-1／Size 可缺失。真实 0 字节与缺失不同；负数、非整数、超 Int64 的 Size 不参与有效比较。未知协议或冲突标记不启用优化。编码、BOM、读取上限及重复字段规则由解析 Task 明确测试，不从文件 mtime 推断版本。
