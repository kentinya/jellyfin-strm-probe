# Slice 5 播放测试及 CI 计划

能力、状态、Base、授权及放行条件以 [Slice 合同](../SLICE.md) 为准。本页细化 RO-1～RO-4 的输入与观测设计，不是活动 Task，也不记录产品 PASS。所有新增真实用例和修复后 CI 当前均 NOT RUN；既往证据仍见 [测试矩阵](test-matrix.md)。

## 复用现有工具

复用 package_environment.py、run_isolated_package_integration.py 和 package_playback_driver.mjs，使用现有隔离部署、ZIP 安装、浏览器登录及点击播放流程。媒体生成采用少量固定 FFmpeg 命令，按下表串行切换输入；重复操作最多补一个直接复用现有函数的简单顺序脚本，截图／音频进度只在现有驱动做必要小改。结果直接保存为场景表、日志及截图，不新增通用测试框架、调度器、场景 DSL、管理界面或独立证据管理系统。此限制与 [Slice 的实施及实播约束](../SLICE.md#实施方式与实际播放约束) 一同验收。

## 环境与夹具自行准备

1. 按 [开发环境](development-environment.md) 核验固定 SDK、Jellyfin／媒体服务镜像锁，记录资源、Docker／浏览器版本及空闲端口。建立有归属标识的独立工作区、内部媒体网络和仅本机暴露的 Jellyfin，不接管现存实例或生产目录。
2. 用锁定 Jellyfin 镜像自带 FFmpeg 合成至少 20 秒媒体：MP4（H.264＋AAC）、MKV（H.264＋AAC）、音频文件（AAC／M4A）；内容有可辨识的画面／音频标记。每类准备 A／B 内容不同版本、逐字节副本和 URL 别名，记录实际内容 SHA-1、字节数及原生媒体信息。只有测试准备脚本计算本地夹具哈希。
3. 准备显式 limited／full ColorRange 视频及未指定该字段的对照，以实际 ffprobe 输出为准，不能凭生成参数声称字段存在／缺失。等 Size 不同内容使用可正常探测播放的等长 A／B，必要时使用合法容器 padding，不伪造内容 SHA-1。优先级用例可有意扰动 Manifest Size，但单列为元数据扰动，不能称为真实文件大小。
4. 本地 HTTP 服务支持 Range、固定 URL 原子切换 A／B、不同路径／查询参数指向相同字节及明确失败路由；禁用掩盖替换的缓存。切换在请求前完成并核验摘要，不在测量窗口异步改写媒体。
5. 自行在临时库目录写版本 1 STRM，标记、URL、SHA-1／Size 与场景一一关联；按需有意省略／写非法可选字段，不混入用户媒体。音频由固定 Jellyfin 原生索引为真实 Audio 项目，先验证其 STRM 支持，不能用视频项目中的音轨冒充；前提无法形成则报告 BLOCKED，不用假对象替代实机证据。
6. 构建候选 ZIP，按现有包环境隔离规则安装，只部署归档负载；核验部署摘要、Active、配置及原生任务默认无触发。原生扫描结束后暂停自动扫描与批量任务，明确项目／源 ID。
7. 除缺主流场景外，在插件禁用的准备阶段通过原生流程建立主流和正确地址，再启用并完成首次信任，固定五字段指纹。明确准备探测与测量的分界，不能先播放一次目标变化偷偷修复前提。

## 八类真实播放矩阵

通常前提为受支持 STRM、插件／播放检查开启、允许探测、已有正确原生地址／必要主流及历史指纹。每个子场景独立恢复基线，测量窗口只串行执行一次明确选源的播放启动，隔离扫描／批量／并发。ffprobe 指该窗口目标源实际进程调用数，媒体 GET 或决策输出不代替计数。

| ID | 场景 | 必测子场景／构造 | 首次测量预期 |
|---|---|---|---|
| P01 | 缺少必要主媒体流 | 视频项目缺 Video、音频项目缺 Audio，分别有／无旧指纹。使用原生未准备流状态，或在已停止的本轮专用副本有界清除目标流并核验；启动后播放前不预取修复。缺 Video 但仍有音轨也要求探测。 | ffprobe=1，保存所需主流，满足条件后提交／初建指纹，实际播放成功。 |
| P02 | URL 变化 | 相同 SHA-1＋相同 Size 内容别名；不同 SHA-1；双侧无可比 SHA-1 且 Size 相同／不同／不可比；仅旧侧或新侧有效 SHA-1；仅查询参数变化。每项独立实机。 | ffprobe=1；当次响应、原生保存及重启均用新 URL／正确主流，新指纹关联新地址。 |
| P03 | URL 不变，SHA-1 相同 | 双侧有效 40 位内容哈希，同值及十六进制大小写变化；Size 相同、不同（明确元数据扰动）、缺失／非法分别覆盖。 | ffprobe=0，复用主流及可信基线，Size 差异不能触发探测。 |
| P04 | URL 不变，SHA-1 不同 | 固定 URL 切换真实 A→B，Manifest 写实际新 SHA-1；Size 相同与不同各一组，另加 Size 不可比，证明 SHA-1 优先。 | ffprobe=1，保存 B 主流与 B 指纹，客户端取得 B 内容。 |
| P05 | URL 不变，无可比 SHA-1，Size 相同 | 新缺／旧有效、旧缺／新有效、双缺及非法 SHA-1；双侧 Size 有效且相同。非法 SHA-1 含长度错误、非十六进制。 | ffprobe=0；暂缺 SHA-1 不抹去同版本历史有效值，不声称识别同 URL 同大小替换。 |
| P06 | URL 不变，无可比 SHA-1，Size 不同 | 固定 URL 切换不同长度媒体，Manifest 字节数同步；覆盖 P05 的不可比方向和新 Size 增／减，明确 ColorRange 视频必须覆盖。 | ffprobe=1，保存并播放当前内容；新版本无有效 SHA-1 时不继承旧版本哈希。 |
| P07 | URL 不变，SHA-1、Size 都无法比较 | SHA-1 不可比；Size 旧缺／新缺／双缺、负数／非整数／Int64 溢出分别覆盖。缺失不是 0；合法 0 的解析另作控制，不把空文件称为可播放媒体。 | ffprobe=0，记录信息不足，正常复用可用主流，不虚构变化或成功探测。 |
| P08 | 仅 Modified 变化 | 仅 STRM mtime 改变、仅可忽略 Modified 注释改变、原字节内容重写／重放；URL／SHA-1／Size 和媒体字节不变。 | ffprobe=0，地址／主流／可信指纹保持，实际播放成功。 |

P01～P08 在 MP4、MKV 视频上逐类执行；音频至少验证 P01 和已有主流复用对照，并对固定版本可原生支持的音频 STRM 执行 P02～P08。B 在实施前固定真实音频输入支持与全部展开行；无法执行的必要项保留 NOT RUN／BLOCKED，不用“八类覆盖”隐藏媒体类型缺口。

子场景清单分配唯一 ID，例如 P02.same-hash、P06.new-sha-missing，一行汇总不能代表全部组合。成功接受新版本后再次播放必须 ffprobe=0。信息不足的跳过不承诺检测后端同 URL 同大小替换。

## 每行观测、播放与重启

- 前置只读快照：Manifest、项目／源 ID、原生 URL／必要主流、五字段指纹、媒体摘要与实际 ColorRange。预期来自独立清单，不从插件输出反推。
- 真实原生 Web 客户端启动对应项目／选源，采集完整请求窗口；不先请求一次 PlaybackInfo 消费目标变化。核对响应状态、MediaSourceId、URL、必要主流与媒体相符。
- 原生进程／编码器证据核对精确 ffprobe 次数、启动与完成，关联目标源及完整日期／会话。浏览器重试、其他项目、准备期及转码 FFmpeg 分开计数；缺证据不能当 0。
- 实际播放时间至少推进 5 秒且有媒体请求；视频有解码帧，音频有 audio 播放进度。每个子场景保留开始及推进至少 5 秒后的浏览器截图，执行者逐项实际打开查看，记录 A／B 画面标记、播放器状态与可见错误；音频截图核对原生播放器界面及进度。失败留报错截图，恢复后重新截图，不能只保存图片而不查看。记录直放／重封装／转码路径，FFmpeg 转码不混入 ffprobe 计数；画面／音频标记和服务端路由摘要确认 A／B 内容。
- 播放后只读核验原生地址／主流、五字段与提交结果。探测行不返回旧地址／旧流，不把未提交说成成功；跳过行保留合法可信基线。
- 每项成功场景再次播放核验无重复探测。重启可按固定矩阵批次统一执行：先冻结全部项目／源完整预期，停止并重启，在任何 PlaybackInfo／播放前只读比对原生地址／流及五字段，再逐项播放核对地址与计数；不能用首次信任或播放补写掩盖丢失指纹。

截图、查看结论、播放进度、ffprobe 计数及原生／指纹状态使用同一子场景 ID／会话关联，正常、ColorRange、恢复、再次播放及重启后均适用。B 独立验收审阅逐行截图及对应结果；缺截图／未实际查看、只有 HTTP 200 或自动化成功标志不得判 PASS。截图避开凭据和敏感地址，保存在本轮忽略的证据目录。

## 已知主流误判与失败恢复

现场涉及插件提交 `2afc6517fda5a7b4170ebea625619a552c47dabc`，定位到 StrmPlaybackOptimizer 的 returnedPrimaryMatchesProbe；规划 Base 中相关 optimizer、ProbeExecutionContext 与编码器／持久化代理代码相同。后续取证绑定实际候选，不能把旧提交上的报告当成新候选已复现。

明确 ColorRange 媒体在 P02、P06 必测，与未指定该字段的媒体对照。前序源码调查指出 Jellyfin 映射可能不保留该字段，而插件按包含 ColorRange 的身份严格比较；静态链路不等于已完成实机复现。

分别保留原生探测主流、SaveMediaStreams 成功返回时的入参、数据库重读／PlaybackInfo 主流，逐字段列出缺失、规范化或数值变化。优先通过隔离诊断／测试观测取得数据，不改插件判定、不补写结果或跳过持久化验证。若日志不足，B 在 Task 明确诊断手段与输入身份；修改插件诊断代码也不能借本规划自动授权。

现场五项日志重现时，区分目标返回源缺失、必要主流缺失、或返回主流字段身份不同。记录 HTTP 500、旧指纹保护及原生地址／媒体流实际保存状态，不能假定异常回滚了 Jellyfin 数据库，也不能假定恢复旧 URL 必然成功。

有效媒体误拒绝为 FAIL，不能靠恢复原 URL、去掉 ColorRange 或只选能通过的夹具记 PASS。另用 404／损坏媒体验证真正失败不提交新指纹，再在同目标 URL 修复媒体并重试，核验重新探测、提交、实际播放及后续零重复探测。产品修复仍待用户决定，未解决缺陷不通过 Slice Final。

## 必要对照

- 首次已有主流信任：零插件探测、初建指纹，不计成功探测。
- 插件禁用、播放检查关闭、普通媒体、旧 STRM：保持原生行为，记录原生可能的探测，不当成插件零探测义务。
- allowMediaProbe=false：通过固定版本真实可用原生入口证明不提高权限、不接受变化，不能伪称 PlaybackInfo 可由客户端任意指定该参数。
- 既有错误源／缺主流、探测失败与相同元数据保存失败控制继续有效。新工具拒绝日志／状态缺失、HTTP 500、错误 URL、仅 HTTP 200 无进度、重启后播放补建状态等伪通过。

## 建议工作包与交接

仅供 B 在 A 激活后裁定，不是已激活 Task：

1. 干净检出 CI 三处失败修复与可复现回归，先恢复反馈；限工作流／测试／必要工具，不混入插件修复。
2. 用现有工具自备媒体／STRM、完成指定 ZIP 安装、核验真实视频／音频输入及原生 Web 播放，增加必要的截图／进度采集小改；不另建环境管理工具或测试框架。
3. 八类矩阵、ColorRange 误判、失败恢复／重启流程及逐行证据、失败拒绝控制，交 B 独立验收。正式 Task 固定入口、命令、等级、资源／超时和 B 全量门槛。

B 每次审查重判剩余 RO，全部满足后准备单独 Slice Final，不另造只用于交接的 Task。工具尚无命令如实说明，不用文档示例冒充执行。因未授权产品修复而失败时，报告阻塞及证据，不签 PASS 或代用户改变范围。

证据持久保存在 `.git/validation-evidence/<source-sha>/<run-id>/` 或稳定 CI 产物，包含逐行清单、输入身份、精确命令／版本／预算、原始请求与脱敏日志、计数／播放进度、已实际查看的截图及结论、三阶段状态、首败／重跑、归属／恢复。媒体、STRM、数据库、缓存和凭据不进普通源码提交；现存 1004 项准备库继续保留。
