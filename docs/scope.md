[V4.3 方案](<../Jellyfin STRM Probe Optimizer V4.3 开发方案.md>) 是当前开发基准；按用户明确授权，仅修订 V4.2 的扫描方式及版本标识，其他方案内容不改。V4.2 原文保留于 `fdcd3fc5576a1eba7835c9e9ff261ac6844a2e96:Jellyfin STRM Probe Optimizer V4.2 开发方案.md`。初始重规划阶段仅修改文档；其后已授权的 Slice 1／2 分别交付核心原型和完整播放／指纹闭环，均经 A 最终审查 PASS / CLOSED。完整产品仍未交付。

V3.0 文件的删除与 V4.2 文件的新增是本轮开始前已有的用户改动。V3.0 原文及旧 Slice／Task 可从重规划前检查点 `4b1d0468c1e43e6e9034ef98e99b6cc44ea59485` 读取，不恢复到工作区。未提供 V4.1 原文，因此以 V4.2 本身写出的规则为准，不补写中间版本历史。

| 旧规划 | V4.2 引入的取舍（V4.3 沿用） |
|---|---|
| URL 改变且 SHA-1 相同只更新路径 | 替代为 URL 改变一律要求原生探测；移除 UpdatePathOnly 与独立 ShortcutPathSynchronizer |
| Assumed／Verified／PendingProbe／ProbeFailed 与观测状态库 | 替代为最小历史指纹；首次信任接管仍存在，不持久化独立探测状态机 |
| 播放期间协调探测 | 播放与批量检查共用决策、提交与协调器；加入全局并发上限 |
| 三个 Slice | 四个 Slice 对应 V4.2 的 P0 核心验证、P1 核心插件、P2 批量任务、P3 集成测试及发布 |
| 生成程序 | 仍明确排除；V4.2 的 P1 是核心插件，不是旧方案的生成器阶段 |

移除状态枚举不移除可靠成功确认义务：失败、取消、解析错误和探测期间变化均不提交新指纹。没有新的成功基线时，后续读取当前 STRM 与旧指纹重新比较即可发现仍需探测，无需另存待测状态。

### 用户授权的批量读取替代

2026-10-14，用户授权 A 调整相关文档并采用更简单方案：原生查询获取所选库的全部候选 ID，去重固定本轮集合，再分批读取完整媒体对象，由固定消费者处理当前批次，不要求额外生产者／等待队列。它替代 V4.2 原文及先前维护文档中的逐页枚举要求；原文及其 SHA-256 保留，不把该变化伪装成已实现事实。候选身份集合允许 O(N) 内存，必须报告集合、去重／排序及原生查询临时分配和耗时；仍禁止全库完整媒体对象物化、全库 Task 和持久化任务状态。

候选集合不是事务快照，新增项目留下一轮，已捕获项目消失／移出范围安全结算；执行前重核范围、当前 STRM／主流／指纹。原生同步查询无取消参数时停止等调用返回，返回后不能准入；已开始或已加入的探测继续保存／提交和汇总，旧轮收尾结束才允许下一轮批量实际运行。完整合同及 Material Contract Change 见 [Slice 3](../SLICE.md#material-contract-change--候选-id-集合与分批读取)。本轮仅修改文档，所有新产品验收仍 NOT RUN。

## 包含

- 只读解析受支持的 STRM 协议、URL、有效内容 SHA-1 和字节 Size。
- 经目标版本验证的播放接入、变化判断、首次信任接管、SQLite 历史指纹与原生按需探测。
- 最新播放地址及原生媒体流的可靠持久化；禁用／故障时的原生委托。
- Jellyfin 原生任务「STRM 媒体信息检查」：手动运行、停止、管理员设置触发时间、所选库候选 ID 集合与分批对象读取、进度和结果。
- 播放／批量只共享已实际开始的运行中探测；排队不共享，已开始探测不因批量停止或等待者退出而取消。插件主动探测并发默认 2、可设 1～8。
- 插件配置、脱敏诊断、隔离大规模／扫描／代理联调与单版本发布材料。

## 排除

- STRM 生成器、OpenList 扫描／元数据 API 客户端、媒体下载与内容哈希计算；插件不写入、移动或删除 STRM。
- JellyfinProxy 代码或缓存配置改造；不缓存完整 PlaybackInfo，不复制原生媒体流。
- 独立任务调度系统、插件独立运行／停止按钮、定时界面及持久化探测成功／失败状态机。
- 首版 ILibraryPostScanTask 自动触发、定期全库无条件探测、跨版本通用二进制承诺。
- 改动生产媒体、生产 Jellyfin 配置或生产数据库。

人工 STRM 夹具与本地假媒体服务仅用于隔离验收，不构成生成器。独立的媒体库扫描与检查时间表不保证顺序完成；管理员在原生任务页安排时间，首版不承诺扫描后自动串行执行。

播放沿用经核对版本的原生取消语义，不增加客户端退出／停止播放到媒体探测取消的关联。当前 PlaybackInfo 不传客户端取消，仍按需决定是否探测；已关闭的 Slice 1 不要求成功返回后的额外取消检查或人为注入取消验收，原生取消异常仍保留基线并传播。按用户本次明确规则，批量停止只撤销未实际开始的工作，已开始探测继续完成并可按全部成功条件提交；只共享已实际开始的探测。A 已修订上层规则及 [Slice 2 合同修订记录](progress.md#slice-2-closed)，取消 Slice 2 人为执行取消源及注入门槛；Slice 3 实测任务停止／收尾，见 [需求](requirements.md#播放与批量取消边界)。
