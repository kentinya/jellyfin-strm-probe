# 核心配置与故障恢复操作说明

本页记录已经 A 最终审查接受的配置操作、原子保存保护、完整配置页及原生任务恢复旅程；配置与任务证据见 [Slice 3 关闭记录](progress.md#slice-3-closed)，最终安装候选的接受范围见 [A Final Review](../SLICE.md#a-final-review)。配置通过 Jellyfin 现有插件配置通道读写；运行／停止／定时使用原生任务界面，已交付的本地单版本包安装步骤见 [安装与恢复说明](package-installation.md)。

## 配置页面

插件通过固定版本 Jellyfin 标准插件页面机制（`IHasWebPages` + 嵌入资源）提供一个配置页，无独立网站或第二套配置服务。

1. 打开「控制台 → 插件」，找到 **STRM Probe Optimizer** 并进入插件详情。
2. 点击页面上的「设置」链接；地址为 `#/configurationpage?name=StrmProbeOptimizer`。
3. 页面加载当前有效配置与真实媒体库列表，编辑五项配置后点击「保存」。

页面展示媒体库名称，保存时写入其稳定 Jellyfin 库 ID。范围修改只对下一轮批量运行生效。显式选择模式下必须至少选择一个库；空选择会被拒绝，不会静默扩大为全部。已保存但已失效的库会以「已失效媒体库」保留在页面上并阻止保存，管理员必须取消失效项并保留至少一个有效库，或明确切换为「检查全部媒体库」后才能保存，因此修改日志等其他字段不会顺便改掉范围。媒体库列表不可读时页面明确提示，显式范围在列表成功重读前不会被保存，也不会被当作全部。加载失败时保存被禁用，不会用默认表单覆盖已保存配置。

页面提供「重新读取」按钮，复用配置与媒体库列表加载逻辑：在保存结果未确认、加载失败或列表读取失败后，管理员可重新读取服务器有效值再决定是否重试。

最大并发探测数按管理员输入的完整数值校验，必须是 1～8 的整数。小数（如 `2.5`）、指数（如 `1e1`）、空值与越界值（`0`、`9`）都会被拒绝且不发送保存请求，不会先截断再保存成另一个值；输入合法值后即可保存。

保存反馈区分三种结果：明确成功显示保存成功与生效时机；服务器明确拒绝（4xx）提示输入被拒绝、需修正后重试；网络错误、超时或无法确认的服务器错误统一提示「保存结果未确认」，不再承诺有效配置未被更改。提交前与提交后响应丢失都以真实有效值为准，不会伪造回滚。

配置页只做配置；运行、停止、定时、进度仍由 Jellyfin 原生「计划任务」页面负责，本插件不提供第二套入口。

## 配置字段

| 字段 | 默认 | 说明 | 生效时机 |
|---|---|---|---|
| `Enabled` | `true` | 插件是否执行 STRM 优化。关闭后保留调用者原始探测权限并委托 Jellyfin 原生处理。 | 保存成功后，下一次检查请求生效；已实际开始的探测继续收尾。 |
| `PlaybackAutoCheck` | `true` | 播放入口是否执行自动检查。关闭只影响播放入口，不影响独立批量入口。 | 保存成功后，下一次检查请求生效。 |
| `MaxConcurrentProbes` | `2` | 插件主动发起的原生探测全局并发上限，合法范围 `1`～`8`。 | 仅在下一次 Jellyfin 启动生效；当前运行的许可池不热调整。配置页与保存反馈都会明确提示。 |
| `DetailedLog` | `false` | 是否输出更详细的复用／加入诊断。必要故障反馈不受此开关影响。 | 下一次检查操作生效。 |
| `BatchAllLibraries` / `BatchLibraryIds` | 全部 | 批量任务检查全部媒体库，或显式选择部分库（一个用户配置项，以稳定库 ID 表示）。 | 对下一轮批量任务生效。 |

固定业务规则（URL 变化必探测、`allowMediaProbe=false` 不升级、SHA-1／Size 比较等）不作为可关闭开关，在配置页以说明展示。

## 原生任务与故障恢复

- 原生任务入口：「控制台 → 计划任务 → STRM 媒体信息检查」。可在该处手动运行、停止、查看进度与历史，并设置触发时间。默认没有自动触发时间，新安装不会自动运行。
- 停止任务只撤销尚未实际开始的工作；已经开始的探测完成保存与指纹提交后任务才以取消结果结束，收尾结束后才能开始下一轮。单项失败修复后可重新运行任务。
- 状态库故障：指纹状态库不可用时批量任务停止后续优化并报告不可用，不退化为全库强制探测。停止 Jellyfin，修复或替换插件数据目录下的 `strm-fingerprints.db`，重新启动后再运行任务即可重试；插件不自动删库或重建。

## 读取与保存（API 通道）

配置通过 Jellyfin 已有端点读写，插件 ID 为 `b061643e-d17d-4c6e-8ba2-6b57e286bd20`。以下示例只使用占位认证，实际令牌由管理员会话提供：

```bash
# 读取当前配置
curl -s -H 'Authorization: MediaBrowser Token="<ADMIN_TOKEN>"' \
  http://127.0.0.1:18096/Plugins/b061643e-d17d-4c6e-8ba2-6b57e286bd20/Configuration

# 保存合法配置
curl -s -o /dev/null -w '%{http_code}\n' -X POST \
  -H 'Authorization: MediaBrowser Token="<ADMIN_TOKEN>"' \
  -H 'Content-Type: application/json' \
  --data '{"Enabled":true,"PlaybackAutoCheck":true,"MaxConcurrentProbes":4,"DetailedLog":false,"BatchAllLibraries":true,"BatchLibraryIds":""}' \
  http://127.0.0.1:18096/Plugins/b061643e-d17d-4c6e-8ba2-6b57e286bd20/Configuration
```

- 合法保存返回 `204`，重新读取可看到新值；并发字段要到下一次 Jellyfin 启动才成为运行上限。
- 越界并发（`0`、`9`、负数）由插件校验拒绝，返回可识别的 `400`，不落盘、不改变当前有效配置。
- 显式选择引用不存在或已失效的库、或空选择时同样被拒绝，不扩大为全部、不改变已保存文件。
- 非整数或字段类型错误由 Jellyfin JSON 反序列化在进入插件前拒绝（`500`），同样不改变有效配置与保存文件。
- 保存失败时候选不生效：插件先把候选完整写入同目录临时文件，成功后才原子替换正式配置；中途写入失败会保留旧有效文件与旧内存配置，并返回错误反馈，重启后仍是旧有效值。

## 重启与生效核对

```bash
python3 scripts/development_environment.py stop
python3 scripts/development_environment.py up
```

重启后核对：

1. `GET .../Configuration` 返回上次成功保存的值。
2. 日志出现插件启动行，写明实际采用的全局并发（`MaxConcurrentProbes` 为本次启动生效值）。
3. 改变 STRM 地址触发一次探测，观察并发行为符合启动值。

已保存非法并发（例如手工编辑配置后写入 `MaxConcurrentProbes=9`）不会被静默接受：启动日志给出诊断并退回默认 `2`，同时保留该非法值以便修正；通过 Jellyfin 重新保存合法值并重启即可恢复。

## 禁用与关闭播放检查的区别

- 关闭 `Enabled`：目标为整个插件停止优化、未开始请求在准入时重读该配置并按原权限委托；已实际开始执行继续收尾。
- 关闭 `PlaybackAutoCheck`：只停止播放入口的自动检查；其他允许入口不受影响。排队播放会在准入时重读该配置并委托。
- 禁用整个插件（Jellyfin 插件管理）：代理注册随重启移除，完全回到原生；独立原生刷新和 Jellyfin／其他插件的探测不受插件并发池限制。

## SQLite 状态库故障恢复

- 运行时指纹库读取或写入异常：插件停止优化并尽可能委托原生，保留调用者权限与旧库文件，不伪造已提交。
- 插件不自动删库或重建损坏库。
- 修复方式：停止 Jellyfin，修复或替换 `data/plugins/<plugin-id>/strm-fingerprints.db`，重新启动，再触发一次播放检查；插件会重新比较当前 STRM 与恢复后的历史指纹。

## 识别限制

- 同 URL 且无可比 SHA-1 时，只有双侧有效 Size 不同才要求探测；信息不足只记录限制，不凭空认定变化。
- 修改时间（mtime）本身不触发探测。
- 日志与证据必须脱敏；启动非法配置诊断只使用插件 ID 与可操作恢复说明，不输出私有配置路径、签名 URL、token 或 Cookie。
