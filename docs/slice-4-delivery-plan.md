## 固定机制与推进方法

### 安装候选先行

- 保持现有 GUID、五项配置、原生任务、SQLite schema、ID 集合／分批和共用 Coordinator。先从当前 Release 输出和已锁依赖形成最小 Linux x64 包；不设计通用插件商店、自动更新器或多平台发布系统。
- 包含插件、实际所需 SQLite 托管／native 依赖、元数据、依赖和适用许可／摘要；不打入 Jellyfin 核心 DLL、FFmpeg、SDK、凭据、数据库、测试或源码。元数据和程序集版本一致，首版可沿用当前 0.1.0.0；版本变化须同步相关输入及验收，不能改 GUID 丢失已有状态。
- 保留“构建／打包”与“消费既有 ZIP 验收”两条显式路径。现有三个实机入口会复制开发构建，不能在包验收中无声调用其 `deploy_plugin()`；只复用不重新部署的 API／断言等函数，或增加明确的包消费模式。所有实例写入前核验归属。
- 建立由仓库派生、与现有隔离实例和生产实例隔开的专用安装验收工作区／Compose project／本机端口。可复用已锁镜像和受控媒体，服务器容器不挂源码、bin／obj、SDK 或 NuGet 缓存。干净安装无预存插件依赖；升级基线是经输入／产物核验的 Slice 3 已接受构建，不把当前候选当作旧版本。
- 后续产品、工具或依赖改变后，重新生成并验证当前候选 ZIP，后续新场景以记录摘要的包部署为主。既有开发部署回归另列；早期包的安装通过不自动证明最后候选可安装。

### 依赖尽早摸底，实施仍按单元闭环

开工时记录当前主机的隔离归属、CPU／内存／磁盘、浏览器和 SDK 可用性；代理摸底仅为旧计划历史，不再是当前准入依赖。2026-10-18 用户授权换机，旧服务器观测和资源阻塞只保留在 Git 历史，不作为新主机准入条件；不要求旧容器、缓存或证据目录存在。已有 Playwright 包不等于 Node／Chromium 可执行链可用，固定新主机实际执行路径与版本，优先复用仓库内测试工具。

本项摸底记录风险，不把无关外部依赖缺失当作 RO-1 的阻塞。代理构建／依赖／缓存和完整联调已撤出，不要求再锁代理运行产物。非代理资源与超时仍在运行前固定留证，真实缺失如实 BLOCKED，部署或下载只能在对应合法工作范围内执行。

### 扫描先小库，大库复用现存准备库

- 4.2 在可控多库／多版本夹具验证完整原生扫描与两入口的真实时间重叠；保留开始／结束／文件变化／实际编码器调用／保存／提交时序，不能用先串行扫完再跑任务替代。有限扰动停止后，对稳定候选重新查询、核验下一轮收敛和重启结果。
- 4.3 按 2026-10-19 用户授权采用至少 1000 个真实原生候选的单一规模门槛，直接复用现存 1004 个受支持库内源，保留全部 1004 项，不截为恰好 1000 项；不再要求另跑更高规模或重复建库。明确建库／准备已有主流与插件信任接管是不同阶段，原生扫描／准备成本单列；数据与主流来自可核验原生扫描／刷新／保存，禁止直接写原生数据库或伪造成功信号。
- 按 2026-10-19 用户明确要求，现存 1004 项准备库及按场景需要保留的一致离线基线（不能把已有指纹的运行后状态当作首次信任前基线）在所有需要使用它的开发阶段复用，不限于当前 Task／Slice 或验收轮次；实施、调试、修复、回归、联调、独立审查、最终验收和发布前验证均持续使用，不因换阶段／角色或代码／工具修改重新建库／全库准备。重复完整场景可整体恢复基线，同次停止／恢复和重启不得还原掩盖错误；每次使用核验前置状态与实际输入并另留结果，旧 PASS 不自动继承。明确交接并核验隔离归属后继续使用，确认后续开发不再需要时才统一清理，不在 Task PASS 或 Slice 关闭时自动清理。长期规则见 AGENTS 和开发流程，当前细节见 TASK；本次不取消其他门槛、实施工具或启动未授权的后续工作。
- 使用测试专用 STRM 夹具与少量复用的合成媒体；仅是隔离验收数据准备，不成为生产生成程序。插件仍不改 STRM、不下载媒体算 SHA-1、不调用 OpenList 元数据 API。
- 继续每批完整对象最多 128、固定消费者最多 8、插件主动探测按启动配置限制。全部 ID／去重／排序及原生查询临时分配按 O(N) 报告，对象／工作、累计分配、采样峰值和总内存分别说明。测量不要求增加持久化监控或独立队列。
- 4.3 按当前 Task 的采样和停止／收尾方案，在新主机运行前记录并固定实际资源与各阶段超时；本方案不虚构普遍性能 SLA，也不绑定旧服务器预算。失败后的环境调整必须说明原因并保留失败，B 审查证据和调整依据；不能悄悄缩小数量、扩大超时、减弱断言或取消安全边界制造 PASS。合同数量／安全义务变化仍交 A。

### 原生媒体验证与代理排除

保留 MP4／MKV 原生 Web 实际播放、逐源 PlaybackInfo／MediaSourceId→URL／必要主流、换地址后首次／重启、失败恢复和多版本选源，由既有 RO-1／RO-3、共同不变量与最后同 ZIP 的 Final 承担。不能只看 HTTP 200 或用播放后补建状态掩盖重启前缺失。

按用户授权不再验证 JellyfinProxy：不新增代理验收脚本，不构建代理／锁其运行依赖，不执行代理 warm-cache、302、GET／Range 或客户端内容对照，不以模拟代理替代。旧计划固定源码及缓存风险只是只读摸底，未实测、无兼容结论；完整计划保留在根 TASK 指定的 Git 快照。插件不改代理／缓存、不调用 OpenList API，OpenList 专有行为仍 NOT RUN。

4. 每份计划按模板给出 Goal、Scope、验收、High／T4、四阶段测试、证据／重跑、非目标和剩余 RO。新的脚本命令明确标为“本 Task 待实现接口，当前 NOT RUN”，不能冒充现有入口或已通过；最终报告用真实路径与实际命令替换规划身份。
