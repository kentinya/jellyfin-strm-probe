## 固定机制与推进方法

### 安装候选先行

- 保持现有 GUID、五项配置、原生任务、SQLite schema、ID 集合／分批和共用 Coordinator。先从当前 Release 输出和已锁依赖形成最小 Linux x64 包；不设计通用插件商店、自动更新器或多平台发布系统。
- 包含插件、实际所需 SQLite 托管／native 依赖、元数据、依赖和适用许可／摘要；不打入 Jellyfin 核心 DLL、FFmpeg、SDK、凭据、数据库、测试或源码。元数据和程序集版本一致，首版可沿用当前 0.1.0.0；版本变化须同步相关输入及验收，不能改 GUID 丢失已有状态。
- 保留“构建／打包”与“消费既有 ZIP 验收”两条显式路径。现有三个实机入口会复制开发构建，不能在包验收中无声调用其 `deploy_plugin()`；只复用不重新部署的 API／断言等函数，或增加明确的包消费模式。所有实例写入前核验归属。
- 建立由仓库派生、与现有隔离实例和生产实例隔开的专用安装验收工作区／Compose project／本机端口。可复用已锁镜像和受控媒体，服务器容器不挂源码、bin／obj、SDK 或 NuGet 缓存。干净安装无预存插件依赖；升级基线是经输入／产物核验的 Slice 3 已接受构建，不把当前候选当作旧版本。
- 后续产品、工具或依赖改变后，重新生成并验证当前候选 ZIP，后续新场景以记录摘要的包部署为主。既有开发部署回归另列；早期包的安装通过不自动证明最后候选可安装。

### 依赖尽早摸底，实施仍按单元闭环

开工时记录当前主机的隔离归属、CPU／内存／磁盘、浏览器和 SDK 可用性、真实代理的来源／版本候选与缺失条件。2026-10-18 用户授权换机，旧服务器观测和资源阻塞只保留在 Git 历史，不作为新主机准入条件；不要求旧容器、缓存或证据目录存在。已有 Playwright 包不等于 Node／Chromium 可执行链可用，固定新主机实际执行路径与版本，优先复用仓库内测试工具。

本项摸底记录风险，不把真实 3000 项媒体库和完整代理联调提前塞入 4.1，也不把无关外部依赖缺失当作 RO-1 的阻塞。4.3／4.4 的计划分别约定资源／超时记录方式和实际代理来源／固定身份；换机后的资源数值由实施者在运行前按新主机固定并留证，无需为环境参数重复请求 B 批准。真实缺失如实 BLOCKED，不能声称已就绪。部署或下载均在对应实施 Task 内进行。

### 扫描先小库，规模逐级增长

- 4.2 在可控多库／多版本夹具验证完整原生扫描与两入口的真实时间重叠；保留开始／结束／文件变化／实际编码器调用／保存／提交时序，不能用先串行扫完再跑任务替代。有限扰动停止后，对稳定候选重新查询、核验下一轮收敛和重启结果。
- 4.3 采用 1000 → 至少 3000 原生候选逐级推进；前一级用于发现准备成本、测量和环境问题，不能替代最后 3000 项验收。明确建库／准备已有主流与插件信任接管是不同阶段，原生扫描／准备成本单列；数据与主流来自可核验原生扫描／刷新／保存，禁止直接写原生数据库或伪造成功信号。
- 按 2026-10-19 用户明确要求，3000 项准备库及首次信任前的一致离线基线在所有需要使用它的开发阶段复用，不限于当前 Task／Slice 或验收轮次；实施、调试、修复、回归、联调、独立审查、最终验收和发布前验证均持续使用，不因换阶段／角色或代码／工具修改重新建库／全库准备。重复完整场景可整体恢复基线，同次停止／恢复和重启不得还原掩盖错误；每次使用核验前置状态与实际输入并另留结果，旧 PASS 不自动继承。明确交接并核验隔离归属后继续使用，确认后续开发不再需要时才统一清理，不在 Task PASS 或 Slice 关闭时自动清理。长期规则见 AGENTS 和开发流程，当前细节见 TASK；本次不取消其他门槛、实施工具或启动未授权的后续工作。
- 使用测试专用 STRM 夹具与少量复用的合成媒体；仅是隔离验收数据准备，不成为生产生成程序。插件仍不改 STRM、不下载媒体算 SHA-1、不调用 OpenList 元数据 API。
- 继续每批完整对象最多 128、固定消费者最多 8、插件主动探测按启动配置限制。全部 ID／去重／排序及原生查询临时分配按 O(N) 报告，对象／工作、累计分配、采样峰值和总内存分别说明。测量不要求增加持久化监控或独立队列。
- 4.3 按当前 Task 的采样和停止／收尾方案，在新主机运行前记录并固定实际资源与各阶段超时；本方案不虚构普遍性能 SLA，也不绑定旧服务器预算。失败后的环境调整必须说明原因并保留失败，B 审查证据和调整依据；不能悄悄缩小数量、扩大超时、减弱断言或取消安全边界制造 PASS。合同数量／安全义务变化仍交 A。

### 真实代理与可控媒体

4.4 的 B 计划先列出实际 JellyfinProxy 来源 URL、不可变版本／源码或镜像摘要、配置身份、网络／端口／后端和准确命令。当前仓库没有固定的代理实现与版本，本方案不宣称任一同名项目已兼容。选定目标后才能作该版本的结论；不能以通用 Nginx／假 302 服务冒充 JellyfinProxy。

使用受控 HTTP 媒体后端即可覆盖本 Slice 的原生契约，OpenList 专有行为在未用真实隔离 OpenList 时维持 NOT RUN。插件、代理代码和缓存策略不改；若既定代理行为阻止正确播放，保留原始结果、准确指出限制并交 A 处理。只验证真实媒体请求，不只看 PlaybackInfo 状态码；比较源身份、URL 摘要、302 与最终字节／Range，使用受控旧地址陷阱确认没有误用旧媒体。

2. 后续 Task Base 使用其实施前真实可达的完整提交 SHA，Contract Checkpoint 指向本方案所在的实际合同检查点；不能提前填写未来 SHA，不移动 Slice Base。新 Task 仅在前一 Task PASS 后计划；修正保留原 Task ID／Base，按提交追加。
3. 本方案的目标、主顺序和验收归属是约束。B 可以据实际状态确定工具位置、精确命令和夹具规模／细节，在同一行为内合并紧密层次；合并／拆分／调整顺序须先在本方案与根 TASK 说明事实、剩余 RO 和证据归属，不能默默漂移或为 P2 增项。若改变合同义务、Required Surface 或当前 Task 边界的验收含义，先交 A 提交 Material Contract Change，再由 B 重判合法性。
4. 每份计划按模板给出 Goal、Scope、验收、High／T4、四阶段测试、证据／重跑、非目标和剩余 RO。新的脚本命令明确标为“本 Task 待实现接口，当前 NOT RUN”，不能冒充现有入口或已通过；最终报告用真实路径与实际命令替换规划身份。
5. 所有 Task 计划保留完整现有 C#／Python 回归、locked restore／Release build／format、治理／差异与三个现有默认实机回归；Developer 只运行改动文件直接影响的聚焦测试并报告省略项，完整套件和新门槛由 B 独立执行。完整套件已覆盖聚焦用例时注明覆盖，不机械重复；包、扫描、大库和代理的新门槛按本单元单独执行。B 独立复现关键风险并核验匹配原始证据，可明确复用合格运行，不默认重复全部昂贵门槛。

## 最终收敛与事实维护

所有修改同一实例、鉴权、配置或触发器的实机串行执行；日志按完整日期／会话关联，记录并验证前后配置、全部触发器、媒体／STRM、临时库条目和恢复。停止只撤销未实际开始工作，已开始工作正常保存和有效提交；原生自身失败／取消仍保护基线。假对象、真实 Jellyfin、3000 项真实媒体库、代理与 ZIP 安装结果分别报告。
