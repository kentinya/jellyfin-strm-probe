# 用户旅程

以下为 V4.2 完整产品 TARGET；Slice 1 核心原型已 PASS / CLOSED，分项事实见 [Closure Packet](progress.md#slice-1-closed)。核心验证通过也不表示完整产品交付。

## 安装与首次接管

管理员选择实测支持的 Jellyfin 版本与插件包。启动日志说明是否成功接入；接入失败明确报告。插件默认启用，播放自动检查默认开启，主动探测并发默认 2。

已有必要主媒体流的版本化 STRM 第一次检查默认信任已有媒体信息并建立历史指纹，不引起全库重探测；该动作不是本次成功探测。配置说明首次信任不能证明已有流一定属于当前远程文件。无主流只在允许探测的执行上下文中走原生探测。

## 播放与地址变化

用户继续使用 Jellyfin 原生播放入口。URL 不变、SHA-1 相同则复用已有流，即使 Size 不同；无可比 SHA-1 时仅比较有效 Size，Modified 不触发探测。

URL 改变始终要求原生探测，包括新旧 SHA-1 相同的移动或签名更新。成功后当次 PlaybackInfo 使用新地址，Jellyfin 保存的新媒体信息与地址在重启后仍有效。首版没有仅更新路径的优化模式。

媒体不可达、失败、探测执行本身取消或探测期间 STRM 再变化时，旧历史指纹保留，不能把旧流冒充新版本成功；修复后，下一次允许的播放或批量检查重新比较并尝试。allowMediaProbe=false 的播放请求不会被插件提高探测权限。新地址保存失败明确反馈，不把旧地址作为新地址成功返回。

获取播放信息按需检查媒体，不会每次都重新探测。当前固定 Jellyfin 版本中，用户退出播放页面或停止播放不会取消已由 PlaybackInfo 启动的媒体探测；停止播放仍由 Jellyfin 管理播放会话和转码。探测如果继续成功且结果已保存、STRM 未再变化，插件仍可接受该指纹，后续播放复用结果。原生探测失败或抛出取消异常时，保留旧指纹以便重试。当前播放原型不增加成功返回后的额外取消检查；后续可取消共享／批量执行保留取消提交保护。

无 SHA-1 且同 URL／同大小的远程替换可能无法识别，说明文档明确该限制。

## 批量检查

管理员打开「控制台 → 计划任务 → STRM 媒体信息检查」，由 Jellyfin 原生入口手动运行、停止，或配置每日／每周触发时间。安装后默认没有自动触发时间；插件配置页不另外提供运行按钮或时间调度器。

任务分页读取选择的媒体库（默认全部），按与播放相同的规则检查 STRM，仅对确实需要探测的项目执行原生探测。第一次运行仍信任已有主流；十万 STRM 不代表十万次 ffprobe。

管理员查看 Jellyfin 原生进度和脱敏统计：检查、跳过、需要、成功、未完成。成功必须证明本次原生结果有效且已保存，首次信任和无法确认的刷新不计成功。取消显示实际进度与未完成情况，不显示全库完成。

播放和批量检查碰到同一媒体源时共享进行中探测；不同源共同遵守插件主动探测并发上限。停止批量任务不应取消仍被播放请求等待的共享工作。该限制不管理 Jellyfin 其他任务或其他插件的 ffprobe。

批量停止会停止后续分页和排队，并结束该任务自身的等待。仍有播放请求等待的共享探测继续执行；它完成且满足全部保存／版本条件后仍可提交指纹，批量任务则按已停止的实际进度报告。

## 配置、禁用与恢复

可编辑项为插件启用、播放自动检查、并发数 1～8、批量媒体库范围和详细日志。固定判断规则、首次信任默认策略与仅按需批量处理以说明呈现，不提供关闭正确性规则的开关。配置保存失败或非法数值有明确反馈；并发变更的生效时机在实施 Task 固定并验证。

关闭播放自动检查仅使播放回到原生，批量任务仍可按插件配置执行；禁用整个插件使播放委托原生，批量不启动插件探测。普通媒体和旧 STRM 默认走原生。SQLite 不可用时停止优化并尽可能原生委托，批量报告不可用；管理员修复后再次检查，不通过清空媒体库恢复。

## 扫描、手动刷新与代理

可分别安排生成器、媒体库扫描和检查任务，但独立时间计划不能保证前一任务已结束。首版没有扫描完成后自动触发；扫描同时变化的 STRM 通过重新读取与旧指纹保护处理。

原生手动强制刷新仍可使用，媒体更新事件不能直接提交当前指纹。JellyfinProxy 继续接收原生 PlaybackInfo、MediaSourceId 与 302 地址；隔离联调验证最新地址，本项目不要求修改代理或缓存策略。
