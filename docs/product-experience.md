# 用户旅程

以下是 TARGET 产品行为，尚未实现。技术验证 Slice 的通过不等于完整插件已交付。

## 安装与首次接管

管理员选择明确支持的 Jellyfin 版本和对应插件包，按该版本的插件安装方式部署并重启。启动日志说明插件是否成功接入；注册失败明确提示该版本是否可用，而不宣称已经安全优化。

已有媒体流的版本化 STRM 第一次播放按默认策略建立 `Assumed`，继续播放；安装插件不会触发全库重探测。没有主媒体流的媒体只在允许探测时走原生探测。

配置页解释 `Assumed` 的限制：已有流未经过当前文件的实证确认。严格首次模式可以成为后续配置，但默认关闭，不能悄悄改变默认接管结果。

## 重复播放和远程替换

播放器仍使用原生播放入口。STRM 与基线一致且必要主流存在时复用已有流；媒体 SHA-1 改变时，在调用允许的条件下探测，再使用确认的新流。

用户无需处理哈希、协调键或数据库状态。无法访问媒体、探测失败或版本在探测期间变化时，系统不能把旧流冒充新版本成功；管理员通过脱敏原因了解失败和待验证状态，修复媒体可达性后由后续允许请求重新检查。

没有 SHA-1 且同 URL／同大小的替换可能无法发现，说明文档明确这一限制。修改时间变化本身不增加播放前探测。

## 内容相同而地址改变

管理员在外部系统移动影片并使现有 STRM 指向新 URL。新旧有效 SHA-1 相同：本次播放使用新地址，媒体流复用，重启后地址依旧正确。路径持久化失败时出现明确失败／原生恢复结果，而不是显示“成功”后仍播放旧地址。

没有两个可比较 SHA-1 时，URL 改变必须要求探测，即使大小相同；这是播放正确性边界，不提供绕过开关。

## 配置、禁用和诊断

管理员在 Jellyfin 插件配置页查看并更改启用、首次接管策略和详细诊断等配置，能识别保存是否成功及何时生效。固定业务规则可解释展示，不做关闭开关。

禁用后版本化 STRM 回到原生处理；普通媒体和无标记旧 STRM 默认一直走原生行为。配置错误或运行时状态库故障给出可操作的原因与恢复方式；诊断不暴露签名 URL 或秘密。

## 手动刷新与外部代理

管理员仍可使用 Jellyfin 手动强制刷新。插件不阻止该动作，也不仅凭更新事件把版本确认成 `Verified`。

使用 JellyfinProxy 的用户仍通过既有播放入口收到 PlaybackInfo 与 302。联调检查最新地址和媒体源身份，不要求普通用户关闭缓存或修改代理。本项目的安装／禁用不能自动改动另一个项目。
