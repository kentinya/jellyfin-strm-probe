# 用户旅程

以下定义 V4.3 及用户后续授权的完整产品旅程。CURRENT：Slice 1／2 已 PASS / CLOSED，播放检查、SQLite 历史指纹、稳定多源、运行中共享／全局并发、核心配置和恢复已交付，分项事实见 [Closure Packet](progress.md#slice-2-closed) 与 [A 最终审查](progress.md#slice-2-closed)。完整配置页、原生批量管理、大规模／代理联调和发布安装仍为 TARGET；[Slice 3](../SLICE.md) 已激活并按用户授权改用 ID 集合分批读取，Task 3.1 合法性与状态见 [TASK.md](../TASK.md)，未形成新实现或验收。核心能力关闭不表示完整产品交付。

## 安装与首次接管

管理员选择实测支持的 Jellyfin 版本与插件包。启动日志说明是否成功接入；接入失败明确报告。插件默认启用，播放自动检查默认开启，主动探测并发默认 2。

已有必要主媒体流的版本化 STRM 第一次检查默认信任已有媒体信息并建立历史指纹，不引起全库重探测；该动作不是本次成功探测。配置说明首次信任不能证明已有流一定属于当前远程文件。无主流只在允许探测的执行上下文中走原生探测。

## 播放与地址变化

用户继续使用 Jellyfin 原生播放入口。URL 不变、SHA-1 相同则复用已有流，即使 Size 不同；无可比 SHA-1 时仅比较有效 Size，Modified 不触发探测。

URL 改变始终要求原生探测，包括新旧 SHA-1 相同的移动或签名更新。成功后当次 PlaybackInfo 使用新地址，Jellyfin 保存的新媒体信息与地址在重启后仍有效。首版没有仅更新路径的优化模式。

媒体不可达、失败、探测执行本身取消或探测期间 STRM 再变化时，旧历史指纹保留，不能把旧流冒充新版本成功；修复后，下一次允许的播放或批量检查重新比较并尝试。allowMediaProbe=false 的播放请求不会被插件提高探测权限。新地址保存失败明确反馈，不把旧地址作为新地址成功返回。

获取播放信息按需检查媒体，不会每次都重新探测。当前固定 Jellyfin 版本中，用户退出播放页面或停止播放不会取消已由 PlaybackInfo 启动的媒体探测；停止播放仍由 Jellyfin 管理播放会话和转码。探测如果继续成功且结果已保存、STRM 未再变化，插件仍可接受该指纹，后续播放复用结果。原生探测失败或抛出取消异常时，保留旧指纹以便重试。不增加成功返回后的客户端或批量停止检查来否决有效提交。批量停止只影响未开始工作；原生探测自身失败／取消异常仍保护旧基线。

无 SHA-1 且同 URL／同大小的远程替换可能无法识别，说明文档明确该限制。

## 批量检查

管理员打开「控制台 → 计划任务 → STRM 媒体信息检查」，由 Jellyfin 原生入口手动运行、停止，或配置每日／每周触发时间。安装后默认没有自动触发时间；插件配置页不另外提供运行按钮或时间调度器。

任务先获取选择的媒体库（默认全部）的候选 ID 集合，再分批读取当前媒体项目，按与播放相同的规则检查 STRM，仅对确实需要探测的项目执行原生探测。候选集合完成前不开始处理；集合固定后新加入的项目留下一轮，删除或移出范围的项目不强行探测。第一次运行仍信任已有主流；十万 STRM 不代表十万次 ffprobe。准备阶段可能要等待原生 ID 查询返回，不承诺立即可开始探测或总内存恒定。

管理员查看 Jellyfin 原生进度和脱敏统计：检查、跳过、需要、成功、未完成，另列候选、不处理、消失／移出、撤销及未读取。准备阶段 0%，其后按本轮候选结算推进，100% 只表示该集合处理结束。成功必须证明本次原生结果有效且已保存并提交指纹，首次信任和无法确认的刷新不计成功。取消显示实际进度与未完成情况，不补成 100%。

播放和批量检查碰到同一媒体源时，只共享实际已经开始且仍在执行的探测；仅排队或等待并发许可的工作不会被作为共享探测。排队请求获得执行机会后重新比较当前 STRM 与历史指纹；此前同源已成功完成时可复用已保存结果。不同源共同遵守插件主动探测并发上限，该限制不管理 Jellyfin 其他任务或其他插件的 ffprobe。

管理员停止批量任务后，不再获取后续候选、读取下一批或启动尚未开始的工作。正在执行的同步原生查询可能要等返回，返回后不开始媒体处理。已经开始的影片探测继续完成，无论是否有播放请求复用；满足全部成功／保存／版本条件后仍提交指纹。批量任务保持正在取消，等待本轮已开始或已加入的探测完成保存／提交与统计，结算释放资源后才恢复空闲、允许下一轮实际运行；独立播放继续沿原规则执行。停止与启动同时发生时，以是否已实际开始区分：未开始撤销，已开始完成。再次运行重新获取 ID 集合和当前文件，不续用旧队列或分页断点。

## 配置、禁用与恢复

完整产品可编辑项为插件启用、播放自动检查、并发数 1～8、批量媒体库范围和详细日志。当前四项核心配置通过 Jellyfin 现有通道保存，操作见 [核心配置说明](core-configuration.md)；完整配置页和批量范围在 Slice 3。固定判断规则、首次信任默认策略与仅按需批量处理以说明呈现，不提供关闭正确性规则的开关。保存失败或非法数值有明确反馈；启用／播放检查／详细日志在保存后的下一请求生效，并发仅在下次启动生效，均已验证。

关闭播放自动检查仅使播放回到原生，批量任务仍可按插件配置执行；禁用整个插件使播放委托原生，批量不启动插件探测。普通媒体和旧 STRM 默认走原生。SQLite 不可用时停止优化并尽可能原生委托，批量报告不可用；管理员修复后再次检查，不通过清空媒体库恢复。

## 扫描、手动刷新与代理

可分别安排生成器、媒体库扫描和检查任务，但独立时间计划不能保证前一任务已结束。首版没有扫描完成后自动触发；扫描同时变化的 STRM 通过重新读取与旧指纹保护处理。

原生手动强制刷新仍可使用，媒体更新事件不能直接提交当前指纹。JellyfinProxy 继续接收原生 PlaybackInfo、MediaSourceId 与 302 地址；隔离联调验证最新地址，本项目不要求修改代理或缓存策略。
