# Developer — 实施经验

以下为本项目核心原型的实施经验。实施方法与测试阶段见 [开发流程](../development-workflow.md)；经验不改变业务规则、范围或审查责任。

- 刷新返回和内存地址可能早于可靠保存 → 在已核对的原生保存事务成功返回后记录信号，关联本次 URL、项目及主流，再检查返回结果与 Manifest 后条件提交 → 适用于固定版本原生探测接入。
- 单元假对象不能暴露完整原生调用链 → 使用隔离合成媒体的实际计数、保存摘要、失败／竞态恢复及真实重启，退出时恢复夹具和地址 → 适用于播放正确性验证。
- 立即获得许可仍可能持有过期输入 → 每个 owner 行动前重读调用者原生源，再读 Manifest／配置／历史基线并重判；首次信任也核对当前版本 → 适用于并发准入和无探测提交例外。
- 实时配置的第二次读取可能抹掉已观测禁用 → 一次读取即保留原因并关闭本轮未开始工作准入，已开始工作仍正常收尾 → 适用于并发批量启停和重新启用。
- 改动范围小但全套回归昂贵 → 先运行新增／修改测试和由改动文件直接影响的测试，明确列出未运行项目并把完整全量回归交给 B → 适用于 Developer 开发反馈，不改变 Task 的最终验收门槛。
- 旧目录标记容易被当成本轮清理权限 → 只认本轮实际新建目录与匹配 token，使用真实 CLI 异常路径验证旧数据不变及本轮正常收尾 → 适用于隔离验收工具的归属与清理。
- 原生字段往返差异可能误拒绝有效结果 → 取同次编码器、成功保存入参与返回完整字段，依据固定版本实证只适配确定的表示差异，保留保存失败保护 → 适用于原生结果匹配修正。
- 配置写入后读回失败不代表未生效 → 在发出写入前建立finally恢复义务，保留实际状态与原错误，恢复无法确认就停止后续行 → 适用于有状态测试编排。
- 累计日志或播放读流可能被误算成探测 → 先固定本轮事件窗口，区分真实探测开始、同源加入与转码读取，缺日志不记零 → 适用于共享与物理探测计数。

每个 Slice 关闭时复盘具体实施事实，只补充 1～3 条可复用的新经验，用“问题 → 做法 → 适用条件”写清。合并重复、替换过时内容，无新经验不凑数。不记录 Task 历史、提交号或测试计数；经验不改变授权、范围或验收门槛。
