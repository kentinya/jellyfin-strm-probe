# Developer — 实施经验

以下为本项目核心原型的实施经验。实施方法与测试阶段见 [开发流程](../development-workflow.md)；经验不改变业务规则、范围或审查责任。

- 刷新返回和内存地址可能早于可靠保存 → 在已核对的原生保存事务成功返回后记录信号，关联本次 URL、项目及主流，再检查返回结果与 Manifest 后条件提交 → 适用于固定版本原生探测接入。
- 单元假对象不能暴露完整原生调用链 → 使用隔离合成媒体的实际计数、保存摘要、失败／竞态恢复及真实重启，退出时恢复夹具和地址 → 适用于播放正确性验证。
- 立即获得许可仍可能持有过期输入 → 每个 owner 行动前重读调用者原生源，再读 Manifest／配置／历史基线并重判；首次信任也核对当前版本 → 适用于并发准入和无探测提交例外。

每个 Slice 关闭时复盘具体实施事实，只补充 1～3 条可复用的新经验，用“问题 → 做法 → 适用条件”写清。合并重复、替换过时内容，无新经验不凑数。不记录 Task 历史、提交号或测试计数；经验不改变授权、范围或验收门槛。
