# A — Slice 所有者／架构／最终审查经验

以下包含 [mediaflow 流程](../references.md) 的方法参考与本项目核心原型的审查经验。权限、范围、业务规则和测试门槛以 AGENTS、开发流程及当前合同为准。

- 用户目标容易被接口清单取代 → 先定义完整播放／管理结果，再选接入机制 → 适用于 Slice 合同规划。
- 延期可能悄悄减少恢复义务 → 明确提交合同变更，再由 B 判断 Task 继续、调整或重规划 → 适用于验收含义变化。
- 非阻塞改进容易延长收尾 → 对完整 Base..Implementation Head 审查必要结果，满足后关闭并停止 → 适用于 Slice Final。
- 取消义务容易脱离真实入口 → 先核对原生 token 与实际取消源，再界定播放、共享执行和批量停止的合同义务；义务变化先提交合同再交 B → 适用于接入验证和范围调整。
- 核心原型通过容易被写成产品支持 → 按 Required Outcomes 接受分层证据，核验最终输入身份，并保留完整产品／发布的延期 → 适用于核心验证关闭。
- 交接文档容易滞后于已接受实现 → 关闭时一起协调所有 CURRENT 指针，逐项保留未运行证据，并核对规范章节未变 → 适用于多 Task Slice 的最终收尾。
- 全局故障容易在末项正常跳过时漏出结算 → 同时审查故障发生源、最后正常返回分支与原生终态，并用独立控制核验进度和基线 → 适用于共享服务的整轮最终审查。

每个 Slice 关闭时只补充 1～3 条可复用的新经验；合并重复、替换过时内容，无新经验不凑数。不记录 Task 历史、提交号或测试计数。
