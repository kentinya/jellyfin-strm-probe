# B — Task 规划／审查经验

以下包含 [mediaflow 流程](../references.md) 的方法参考与本项目核心原型的独立审查经验。经验不能替代合同、实际代码或原始证据。

- 按文件拆任务会打断用户结果 → 从已提交 Slice 选择跨必要层的完整行为 → 适用于 Task 规划。
- 重复全量验证增加等待但未必增加证据 → 按风险安排开发反馈和最终门槛，独立复现关键行为并核验匹配证据 → 适用于审查与修正循环，不能削减 T4 门槛。
- 范围问题被误当成测试问题 → 交回 A 修改合同，再明确判断 Task 合法性；每次 PASS 重新检查全部 RO → 适用于发现义务变化或决定停止规划。
- 旧主流可能与本次结果完全相同 → 保存失败对照使用相同元数据，连续验证拒绝、保留基线与允许重试，并核对原生事务边界 → 适用于刷新可能吞掉保存异常的接入。
- 探测计数无法展示 FullRefresh 附带工作 → 同时观察提供器调用与端到端计数，恢复诊断配置，区分调用、完成与成本 → 适用于原生刷新开销审查。
- 异步准入缺陷可能被最终绿灯掩盖 → 用屏障独立复现立即获许可、同源先完成及取源期间变化，并断言探测次数、基线与资源结算 → 适用于共享协调审查。
- 构建版本标识会使相同源码产物字节不同 → 核对源码输入并以原 SourceRevisionId 重建后比较摘要，明确复用范围 → 适用于跨检查点证据交接。
- 长验收可能混入旧日志或并行鉴权干扰 → 以完整日期／会话关联日志并隔离鉴权身份，保留首次失败和重跑 → 适用于跨日或重启的真实集成。

每个 Slice 关闭时只补充 1～3 条可复用的新经验；合并重复、替换过时内容，无新经验不凑数。不记录 Task 历史、提交号或测试计数。
