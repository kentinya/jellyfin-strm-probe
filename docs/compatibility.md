任务先记录隔离服务器实际版本／镜像 digest、相应源码提交、目标框架、插件 NuGet 版本与 SDK，再选择一个验证目标。另一版本保留候选状态，不宣称同时兼容。

## Slice 1 验证表

| 问题 | 必须取得的证据 | 状态 |
|---|---|---|
| 核心 DI 接入 | 注册顺序、单一原生实例、无循环依赖、正确释放、所有接口委托、启动／关闭、普通媒体／直播原生行为 | NOT RUN |
| 跳过重复探测 | 已有主流的版本化 STRM 二次播放，实际 ffprobe 次数为零增量，MediaSources 有效 | NOT RUN |
| 主动探测 | 必须探测路径上确认原生 ffprobe 实际执行，不靠 true 参数猜测 | NOT RUN |
| 成功验证信号 | 故意制造失败且保留旧流、真正成功、取消和前后 Manifest 变化的对照记录 | NOT RUN |
| 路径持久化 | 相同 SHA-1 换 URL，当次 PlaybackInfo 新 URL，原流保留，重启仍是新 URL | NOT RUN |
| 禁用与探测权限 | 禁用恢复原生；allowMediaProbe=false 不启动探测 | NOT RUN |

若原生刷新吞掉错误，必须找到可可靠关联到本次探测的新结果信号。找不到时记录阻塞，不能仅凭旧流存在宣布成功。FullRefresh 的其他提供器开销也须记录。

## 版本发布边界

每个发布包只声明已实测的服务器范围；核心接口／DI 变化后重新验证。发布材料要有准确 SDK、依赖锁定、安装与禁用恢复步骤，以及未完成的客户端／代理兼容项。
